**Date:** 2026-07-07
**Branch:** `feat/position-coordinates-genome-map`
**Scope executed:** Stage 2 of
[`plans/optimize_add_offspring.md`](optimize_add_offspring.md) — replace the base-R
gamete RNG in `add_offspring()` with a **`dqrng` per-gamete-stream** kernel, add opt-in
crossover-event storage (`ind_crossover`), and add the seed API. This is the **first
intentional seeded-output change**: for a fixed seed, offspring `ind_haplotype` differs
from 0.51.0. Per CLAUDE.md's pre-1.0.0 stance there is no cross-version output guarantee —
only forward reproducibility (same seed reproduces on the current code) and (from Stage 3)

**Chosen approach — leaner dqrng swap** (user decision, 2026-07-07): keep the current
per-parent haplotype-matrix structure and Stage-1's wide→long reshape; swap only the RNG
source, add `store_crossovers` + `ind_crossover` writes + the seed API. The packed parent
arrays / group-by-map calls / integer `line_origin` codes / long-native seam output are
**deferred to Stage 3**, where the C++ boundary actually needs them. Output changes exactly
once (now); Stage 3 reproduces it byte-for-byte (same algorithm + streams, different memory
layout).

**Seed persistence — surface only** (user decision): `seed = NULL` draws one base seed from
base-R RNG (so an upstream `set.seed()` reproduces the run); the resolved seed is reported +
attached as `attr(pop, "base_seed")`, never written to any table (honors CLAUDE.md's
no-metadata stance).

## What changed

### RNG model — per-gamete `dqrng` sub-streams (Scheme A)
The unit of randomness is a gamete `(offspring o, parent_origin r, stream_kind k)`:
autosomes use `k = 1`, special chromosomes use `k = 2` (an independent sub-stream). The
tuple is folded to a scalar stream id `sid = ((o*2 + (r-1))*2 + (k-1))` and seeded with the
2-int seed `c(base_seed, sid)` via dqrng's own `convert_seed` (`dqRNGkind("Xoroshiro128++")`
+ `dqset.seed`) — the exact Scheme A the spike (`dev/spikes/dqrng_parity/`) proved
bit-identical R↔C++. `o` is the **global** `matings` row index, so output is identical for
any `batch_size` and iteration order (and, from Stage 4, any thread count).

### Kernel — `R/recombination_helpers.R`
Kept the three functions and their roles; swapped internals to dqrng and added a crossover
buffer. New internal helpers:
- **`.gamete_stream_id(o, parent_origin, kind)`** — folds the tuple to `sid`.
- **`.seed_gamete_stream(base_seed, sid)`** — sets the dqrng kind + 2-int seed for one gamete.
- **`.draw_poisson_dqrng(lambda)`** — **log-accumulation inversion Poisson sampler** consuming
  only dqrng uniforms (no base `rpois`). `lambda <= 0` → `0` (no draw). Errors above a
  documented ceiling of 30 Morgans (3000 cM). This is the exact sampler the Stage-3 C++
  kernel must mirror.
- **`.draw_chr_recombination(chr_pos, chr_len, store_crossovers)`** — the per-chromosome core
  (count → start homolog `u < 0.5` → sorted positions), drawing from the already-seeded
  stream; returns `hap_idx_vec` (+ crossover cM positions). Shared by autosomes and
  recombining special chromosomes.
- **`make_gamete()`** now seeds its gamete's stream once and loops chromosomes via the core;
  returns `allele`, `homolog`, and (when `store_crossovers`) `xover_chr_idx`/`xover_pos_cM`.
- **`make_gametes_batch()`** gains `base_seed` + `o_index` + `store_crossovers`; returns the
  same four wide matrices plus an optional `crossovers` frame `(local_j, parent_origin,
  chr_idx, pos_cM)`.
- **`pass_through_gamete()`** now draws from the **current (caller-seeded)** stream: `k == 2`
  → one dqrng uniform (`u < 0.5`) chooses the homolog; `k == 1` → no draw.

### `add_offspring()` — `R/add_offspring.R`
- **Signature:** `add_offspring(pop, matings, seed = NULL, store_crossovers = FALSE,
  batch_size = NULL, max_batch_mem = NULL)`. Resolves `base_seed` at the top (`seed = NULL` →
  one `sample.int` draw from base-R; explicit `seed` used directly, no base-R draw).
  Surfaces it via message + `attr(pop, "base_seed")`.
- **Autosome/special restructure.** Because per-gamete streams make draw order irrelevant,
  the Stage-1 `if (special) per-offspring-batch-of-one else full-batch` branch is gone:
  autosomes are **always** generated by one `make_gametes_batch()` over the whole batch
  (`k = 1`); special chromosomes run in a separate per-offspring loop on the `k = 2` stream,
  **seeded once per `(o, parent_origin)`** and drawing that gamete's special chromosomes in
  ascending-chr order (never re-seeding per chromosome — that would collide).
- **`ind_crossover` writes (opt-in).** When `store_crossovers`, the batch's crossover events
  (autosomes from the kernel + recombining special chromosomes) are written to
  `ind_crossover` in the same transaction, `id_crossover` assigned via the BIGINT-safe
  allocator. `chr`/`chr_name` come from the existing chr descriptors (no `genome_meta` join).

### `.write_crossovers()` — `R/haplotype_write_helpers.R`
New shared helper: assigns `id_crossover` via `next_row_id()`, registers the frame, one
`INSERT` into `ind_crossover`. RNG-neutral; within the transaction, ids stay sequential
across batches.

### BIGINT-safe id allocation — `R/sql_utils.R`
Added **`next_row_id(conn, table, id_col)`**, a sibling of `next_int_id()` that returns a
**double** instead of `as.integer()` — which would have returned `NA` once
`MAX(id_crossover)` exceeds `2^31`, defeating the `BIGINT` PK. Used for `id_crossover`
(exact to `2^53`).

- **`test-sex_chromosomes.R`** — the two `pass_through_gamete()` RNG-coupled tests rewritten

  exactly one uniform and chooses via `u < 0.5`). Y/W/MT inheritance-relation tests unchanged.
- **`test-recombination_dqrng.R`** (new, 74 assertions):
  - Poisson sampler: mean/var ≈ `lambda` at `{0.3, 1, 5}`, `lambda = 0` → 0, ceiling error,
    stream reproducibility.
  - Seed API: explicit seed reproducible and independent of surrounding base-R state; a
    different seed changes output; `seed = NULL` reproducible under an upstream `set.seed()`
    (same drawn `base_seed`).
  - Crossover storage: `store_crossovers` populates `ind_crossover` with the right columns +
    unique BIGINT ids, mean crossovers/gamete-chr ≈ Poisson(len_M), positions in `(0, len)`,
    and **no** side effect on `ind_haplotype`.
  - Crossover ↔ haplotype consistency on a controlled fixture (homologs differ at every
    marker): recorded crossover positions delimit exactly the observed homolog switches.
- **Structural tests** (`test-add_offspring.R`, `test-long-writers.R`,
  `test-dosage_extract_parity.R`, `test-haplotype_write_helpers.R`) stay green unchanged.

### Runtime (no kernel regression)

Phase 0 established gamete generation is <5% of `add_offspring()`; Stage 2 confirms the
dqrng swap did not change that:

| micro-benchmark | result |
|---|---|
| 2000× `dqRNGkind` + `dqset.seed` | 0.008 s |
| 100k `dqrunif(1)` one-at-a-time | 0.14 s |
| `add_offspring(500 off × 5000 loci × 10 chr)` | ~9 s — DB-write-dominated (unchanged from Stage 1) |
| same, `store_crossovers = TRUE` (10,005 crossover rows) | ~12 s |

The RNG overhead is sub-second; total wall time is the Stage-1 long-write floor for 5M
`ind_haplotype` rows, not the kernel.

## Deferred to Stage 3 (explicitly not in this stage)

Packed homolog-major parent arrays, integer `line_origin`-code dictionary,
group-by-resolved-map calls, and long-native kernel output — all the machinery the C++
boundary needs. In v1 every gamete resolves to the single default map, so the
per-`(sex,line)` resolution already in `add_offspring()` still runs; Stage 2 just keeps
feeding it the current per-parent matrices. Stage 3 is a contained port: the dqrng spike +
this R reference (the parity oracle) + the pinned Scheme A make the C++ kernel a
byte-for-byte match, output-neutral vs Stage 2.
